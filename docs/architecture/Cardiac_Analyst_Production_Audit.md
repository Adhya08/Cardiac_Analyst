# Cardiac Analyst production-readiness audit

**22 November 2026 IST · Source revision `26b71048e6261cdf5b77193252d3dd1382c8d018`**

**Release decision:** The public service is reachable. The current evidence supports a research demonstration using public or synthetic examples. Patient-facing diagnosis, absolute cardiovascular risk estimates and emergency routing have unresolved release blockers.

The audit combines public read-only HTTP checks, a fresh GitHub checkout, static tracing, an isolated local test run against SQLite and comparison with the provided training notebook. No project code, commits, settings, production accounts or health records were changed. No report or location was submitted to external services.

## A. Architecture assessment

The Vercel frontend is a React 19, Vite and TypeScript SPA. Zustand selects the dashboard mode and persists preferences alongside user and clinical state. The shell exposes Overview, Routine, ECG, History and Emergency, with a profile and authentication modal. The ECG renderer and charts live in the browser. The waveform classifier runs in FastAPI via ONNX Runtime on the server. One same-origin API client targets `/api/v1`. Vercel rewrites that namespace to the Render host named `cardiac-backend-staging`; Netlify carries a parallel configuration. SQLAlchemy supports PostgreSQL and defaults to a local SQLite file. Browsers execute a TypeScript fallback for questionnaire logic using the same JSON rules as Python. MapLibre draws map tiles and provider-derived points. This fallback requires an already loaded application. The service worker clears caches and unregisters itself, so cold offline access has no supporting cache strategy.

The current source intends optional Groq explanations, Geoapify search and OpenFreeMap tiles. The live backend identifies Sarvam and reports its configuration missing. Source behavior and deployed behavior must therefore be tracked independently.

Evidence: [SPA entry](https://github.com/Adhya08/Cardiac_Analyst/blob/26b71048e6261cdf5b77193252d3dd1382c8d018/src/App.tsx), [store](https://github.com/Adhya08/Cardiac_Analyst/blob/26b71048e6261cdf5b77193252d3dd1382c8d018/src/store/useStore.ts), [API client](https://github.com/Adhya08/Cardiac_Analyst/blob/26b71048e6261cdf5b77193252d3dd1382c8d018/src/lib/api.ts), [Vercel rewrites](https://github.com/Adhya08/Cardiac_Analyst/blob/26b71048e6261cdf5b77193252d3dd1382c8d018/vercel.json), [FastAPI entry](https://github.com/Adhya08/Cardiac_Analyst/blob/26b71048e6261cdf5b77193252d3dd1382c8d018/backend/app/main.py), [service worker](https://github.com/Adhya08/Cardiac_Analyst/blob/26b71048e6261cdf5b77193252d3dd1382c8d018/public/sw.js).

## C. Critical bugs and security concerns

1. **Chat rejects legitimate consent.** The consent helper raises on failure and returns None on success. The message endpoint interprets that return as false and returns 403 before calling the explainer. Local deterministic summary also requires third-party consent before deciding whether cloud processing will happen. The cloud path checks caller consent before loading a record the caller can access as clinician or admin. Define how the data subject authorizes provider disclosure and test that this permission is distinct from read access. [Consent helper and call sites](https://github.com/Adhya08/Cardiac_Analyst/blob/26b71048e6261cdf5b77193252d3dd1382c8d018/backend/app/routers/chat.py#L101-L234)
2. **Map popup trusts provider text as HTML.** The map interpolates names, addresses and links into a string passed to MapLibre `setHTML`. This is a source-confirmed unsafe sink. Token and profile information are kept in browser storage, and the persisted Zustand store includes vitals and risk history. No live payload or exploit was attempted. Build popup content with text nodes and validated URL destinations. Limit browser persistence to non-sensitive UI preferences and design revocable sessions. [Map popup](https://github.com/Adhya08/Cardiac_Analyst/blob/26b71048e6261cdf5b77193252d3dd1382c8d018/src/components/HospitalMap.tsx#L129-L159) · [Auth client](https://github.com/Adhya08/Cardiac_Analyst/blob/26b71048e6261cdf5b77193252d3dd1382c8d018/src/lib/api.ts#L192-L246) · [Persisted state](https://github.com/Adhya08/Cardiac_Analyst/blob/26b71048e6261cdf5b77193252d3dd1382c8d018/src/store/useStore.ts)
3. **ECG files are retained before acceptance.** The API reads the upload into memory before enforcing its 20 MB application limit, writes a local copy before analysis, and stores bytes again in SQL. Rejected formats can enter this write path. Failed SQL writes can leave an orphaned local copy, with response text constructed from the raw exception. Top-condition selection also compares scores without requiring the finding to be detected. Reject oversized and unsupported data before durable writes, enforce bounded ingress, and return stable errors. Clarify whether history shows thresholded findings or a ranked score. [Upload implementation](https://github.com/Adhya08/Cardiac_Analyst/blob/26b71048e6261cdf5b77193252d3dd1382c8d018/backend/app/routers/ecg.py#L26-L139)
4. **Hospital status and distance can mislead.** The Geoapify mapping assigns every result 4.5 stars, 100 ratings and `open_now=True`. The map presents this as “24x7 Emergency.” A generic hospital category does not establish cardiac emergency capability. Empty results can substitute Delhi NCR entries while preserving provider attribution as the source, and the regional fallback ignores the radius. The browser can reuse prior hospital results without a location-aware expiry, including links containing origin coordinates. Return unknown capability and hours, preserve actual source and freshness, enforce radius and drop unsupported ETA claims. [Places service](https://github.com/Adhya08/Cardiac_Analyst/blob/26b71048e6261cdf5b77193252d3dd1382c8d018/backend/app/services/places_service.py) · [Map](https://github.com/Adhya08/Cardiac_Analyst/blob/26b71048e6261cdf5b77193252d3dd1382c8d018/src/components/HospitalMap.tsx) · [Browser fallback](https://github.com/Adhya08/Cardiac_Analyst/blob/26b71048e6261cdf5b77193252d3dd1382c8d018/src/modes/EmergencyMode.tsx)
5. **SOS throws before producing hotline guidance in HEAD.** The local public SOS test reproduced a NameError for the removed hospital lookup. Live SOS was not called. Fix the stale reference and verify SOS can always return contacts even if places lookup fails. The current release also has a network timing issue. The triage API computes the assessment and then waits synchronously for hospital discovery before responding. UI fallback follows request failure, and the generic client has no explicit deadline. Show escalation and call links independently of network and map success. Separate provider fetches from the decision and use a bounded timeout with visible degradation. [Emergency router](https://github.com/Adhya08/Cardiac_Analyst/blob/26b71048e6261cdf5b77193252d3dd1382c8d018/backend/app/routers/emergency.py) · [API client](https://github.com/Adhya08/Cardiac_Analyst/blob/26b71048e6261cdf5b77193252d3dd1382c8d018/src/lib/api.ts)
6. **Release and schema drift can make checks misleading.** Startup uses create_all plus best-effort ALTERs, prints migration errors and continues. The backend Dockerfile assumes a backend-local build context, which by itself omits the required repository-level shared triage JSON. The hard-coded Vercel proxy points at a staging-named host, and the app reports readiness via a different ECG loader than upload. Establish one clean build, migration, artifact and service-readiness contract. [Database](https://github.com/Adhya08/Cardiac_Analyst/blob/26b71048e6261cdf5b77193252d3dd1382c8d018/backend/app/database.py) · [Triage rules loader](https://github.com/Adhya08/Cardiac_Analyst/blob/26b71048e6261cdf5b77193252d3dd1382c8d018/backend/app/ml/triage.py) · [Dockerfile](https://github.com/Adhya08/Cardiac_Analyst/blob/26b71048e6261cdf5b77193252d3dd1382c8d018/backend/Dockerfile)
7. **Patient data lifecycle and provider boundaries are underspecified.** Current flows can retain account identifiers, clinical history, raw ECG data and triage coordinates. Coordinates enter query strings for nearby search and outbound navigation links. Provider exception strings and raw response bodies merit redaction review. The access helper grants admins cross-patient access and falls back to placeholder path/IP metadata when request context is omitted. Restrict privileges, distinguish data access from transfer permission, and log identifiers and result codes with explicit retention and redaction. ## D. Medical AI validity

**ECG.** The repository reports 2,158 test records from 1,877 people on PTB-XL fold 10, with macro AUROC 0.9265, AUPRC 0.8196 and F1 0.752. Thresholds were reportedly chosen on fold 9, consistent with PhysioNet’s recommended split. The report gives 110 misses among 550 MI-positive records and 116 among 262 HYP-positive records. These are repository-reported results. The five-class 100 Hz waveform benchmark does not validate clinical decisions, onset timing, paper scans, consumer wearables or measurements such as QTc and lead localization. The source can present “acute myocardial injury/infarction” from an MI label and “NORMAL” when no abnormal label fires, even without a separate positive normal decision. Update copy to reflect actual label scope, uncertainty and unsupported inputs. NICE explicitly states a normal resting ECG cannot exclude ACS. The repo also reports raw-score overconfidence. Verify model provenance, calibration, patient-cluster uncertainty and performance on a compatible independent cohort, with signal-quality and subgroup results. [Evaluation](https://github.com/Adhya08/Cardiac_Analyst/blob/26b71048e6261cdf5b77193252d3dd1382c8d018/backend/models/EVALUATION_REPORT.md) · [Analyzer decision logic](https://github.com/Adhya08/Cardiac_Analyst/blob/26b71048e6261cdf5b77193252d3dd1382c8d018/backend/app/ml/ecg_analyzer.py#L246-L325) · [PhysioNet](https://physionet.org/content/ptb-xl/1.0.3/) · [NICE CG95](https://www.nice.org.uk/guidance/cg95/chapter/recommendations)

**Vitals.** The UCI classification outcome concerns disease presence, while the UI claims 10-year ASCVD risk. Runtime takes a 60:40 blend of a modified Framingham result and the classifier probability, then adds smoking and family-history increments. It estimates HDL, assumes no BP treatment and invents catheterization, perfusion, stress and ECG predictors from resting vitals. It labels a fixed ±4.5-point band a confidence interval, and the fallback returns heuristic feature effects through a SHAP-shaped field. Also, `backend/train.py` saves a calibrated ensemble and fits a separate LightGBM for SHAP, so those attributions cannot explain the returned ensemble blend as a whole. Disable absolute risk and misleading attribution labels for a public release. If a score is required, select one validated equation for the intended endpoint and population, collect its actual inputs, show explicit ineligibility and verify input/output reference cases and local calibration. [Training](https://github.com/Adhya08/Cardiac_Analyst/blob/26b71048e6261cdf5b77193252d3dd1382c8d018/backend/train.py) · [Risk implementation](https://github.com/Adhya08/Cardiac_Analyst/blob/26b71048e6261cdf5b77193252d3dd1382c8d018/backend/app/ml/risk_model.py) · [UCI dataset](https://archive.ics.uci.edu/dataset/45/heart+disease) · [Framingham study](https://pubmed.ncbi.nlm.nih.gov/18212285/)

**Triage and explanation.** Rule parity tests check software behavior. They do not validate triage safety on real patients. The backend produces numeric confidence/risk and a STEMI-suspicion flag from rules and symptoms. Those scores have no demonstrated clinical calibration. Model and rule output should never suppress urgent escalation in a symptomatic user. For optional explanations, guardrails that scan for a few terms do not establish faithful multilingual summaries. Use structured outputs anchored to recorded findings, evaluate harmful omissions and unsupported additions, and keep deterministic explanations available without provider access. [Rule engine](https://github.com/Adhya08/Cardiac_Analyst/blob/26b71048e6261cdf5b77193252d3dd1382c8d018/backend/app/ml/triage.py) · [Groq implementation](https://github.com/Adhya08/Cardiac_Analyst/blob/26b71048e6261cdf5b77193252d3dd1382c8d018/backend/app/ml/groq_explainer.py) · [NICE CG95](https://www.nice.org.uk/guidance/cg95/chapter/recommendations)

## E. Production-readiness gates

| Gate | Required evidence before promotion |
|---|---|
| Scope and clinical safety | Name the audience and intended use. For a public research demo, use authorized samples and neutral output. Patient-facing use requires separate clinical and applicable regulatory review with documented release ownership. |
| Reproducible deployment | Pin Node/npm and Python dependencies, prove fresh build from one SHA, stamp UI/API/model/rules revisions, run one versioned migration job, compare public probes with the approved release and rehearse rollback. |
| Access and patient data | Verify cross-user isolation, grant scope and expiry/revocation in staging. Validate storage encryption, backups/restores, audit completeness, account lifecycle, retention and deletion in a dedicated environment. |
| Provider failure | Exercise missing keys, denied location, timeouts, 429s, empty/malformed results and outage. Keep waveform inference, neutral explanations and emergency contact actions independent of optional providers. Provider quota and data-handling terms require separate confirmation. |
| Operational controls | Instrument latency, 4xx/5xx, dependency degradation, upload/persistence failures, migration status and access events. Run synthetic checks without PHI. Alert on failure by release and service. Report liveness separately from readiness and optional degradation. |
| ML validation | Freeze one artifact/preprocess/threshold bundle. Preserve held-out lineage, run framework parity and evaluate generalization and real input fidelity. Prove clinical claims separately from test suite parity. |

Provider references: [Groq rate limits](https://console.groq.com/docs/rate-limits), [Geoapify Places](https://www.geoapify.com/places-api/), [Google Places billing and quotas](https://developers.google.com/maps/documentation/places/web-service/usage-and-billing/). A configured key alone does not establish quota, availability or permission to transfer patient data.
